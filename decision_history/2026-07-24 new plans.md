## §40 `core/console.py` — the abstract console classes

### §40.1 `ConsoleStream` — one growable capture

¶10 🤖 Bytes underneath, decoded views on top, appendable for the lifetime of the object:

```python
class ConsoleStream:
    def feed(self, data: bytes) -> None      # called by the producer's sink

    @property
    def bytes(self) -> bytes:   """Verbatim, exactly as produced."""
    @property
    def decoded(self) -> str:   """UTF-8 decoded; escape sequences intact (colours)."""
    @property
    def text(self) -> str:      """Decoded, escapes stripped, CR overlays applied."""
    def __len__(self) -> int                 # byte length; slice anchor for minutes
```

¶20 🤖 Implementation is a `bytearray` plus an **incremental** UTF-8 decoder and a materialised text tail — *not* `TextIOWrapper` over `BytesIO` (👤's "maybe"). Reason: a `TextIOWrapper` wrapping a still-growing `BytesIO` needs read/write position juggling on every access, and it re-decodes from a seek point rather than carrying decoder state, so a multi-byte character split across two PTY reads decodes wrongly. The incremental decoder is what the current code already uses and is the reason split UTF-8 works today.

### §40.2 `StreamSet` — the three streams

```python
class StreamSet:
    stdout: ConsoleStream
    stderr: ConsoleStream
    combined: ConsoleStream       # temporal interleave, always present

    separated: bool               # False when the source is a PTY
    def feed(self, fd: Literal[1, 2], data: bytes) -> None
```

¶10 🤖 `feed()` appends to the per-fd stream **and** to `combined` in arrival order, which is what preserves the interleave. When `separated` is False only `combined` is populated, and `stdout`/`stderr` raise `UnsupportedOperation` with a message naming the reason — a PTY merges the two in the kernel, so returning `combined` under the name `stdout` would be a quiet lie.

| implementation | separated |
|---|---|
| `Session` (PTY) | no — combined only |
| `RunSession` (PTY capture) | no — combined only (👤: "`CommandResult` only has combined") |
| `ExecSession` (OSC O/X demux) | **yes** |
| `ForkSession` (FIFO trio) | **yes** |

### §40.3 `AbstractConsoleOutput`

¶10 👤 "All these can be in the abstract class, fed by callbacks given to the sub-classes (to better work with the filter architecture)." — the ABC owns the buffers; producers are handed a sink and never touch storage:

```python
class AbstractConsoleOutput(ABC):
    kind: ClassVar[str]                  # "session" | "run" | "exec" | "fork"
    separated: ClassVar[bool] = False

    session_name: str
    command: Optional[str]
    streams: StreamSet
    returncode: Optional[int]

    @property
    def sink(self) -> Callable[[int, bytes], None]:
        """Hand this to whoever produces the bytes — a filter terminus, an OSC
        handler, a FIFO drain thread. The only way data enters."""
        return self.streams.feed

    # --- completion ---------------------------------------------------
    def __await__(self):                 # 👤: awaitable object
        """``rc = await run_session``"""
    @property
    def done(self) -> bool
    @property
    def ok(self) -> bool

    # --- notebook rendering -------------------------------------------
    @property
    def label(self) -> str:
        """The heading line, e.g. ``$ make test`` — overridable per subclass."""
    def _cell_plain_output(self) -> str
    def _cell_json_output(self) -> Dict[str, Any]
    def _repr_mimebundle_(self, include=None, exclude=None) -> Dict[str, Any]
```

¶20 🤖 👤's review points applied: `_display_kind` is now the `kind` **class variable** (static, so not a method); `_display_header` is the `label` **property**; `_display_blocks` is **gone** — with a real `combined` stream there is no "--- stderr ---" section to assemble, because the interleave already holds it; `_plain`/`_json` are renamed `_cell_plain_output`/`_cell_json_output`.

¶30 🤖 There is no `poll()`/`wait()`. Completion is `await`. See §90 ¶30 for the one place this is genuinely awkward.

¶40 🤖 `AbstractProcessConsole(AbstractConsoleOutput)` adds what only a live process has: `stdin` (text layer plus `.raw` byte layer), `send`, `sendline`, `pid`, `send_signal`, `terminate`, `kill`, `close`. Implemented by `Session` and `ForkSession`. `RunSession`/`ExecSession` deliberately have no input — the harvest records that an exec's far end closes its stdin immediately.

¶50 🤖 This collapses four near-duplicate `_plain()` and four near-duplicate mimebundle implementations currently spread across `sub_sessions.py` and `fork.py`.

## §50 The core framework

### §50.1 The two interfaces — who implements what

¶10 👤 "`FeatureHost` — Is it the API that each feature calls or an abstract class each implements? The sample code seems like a mix of both, which can't work." Correct; the split is now strict:

| | implemented by | called by | contains |
|---|---|---|---|
| `FeatureHost` | the **framework** | features | every imperative verb — registration, actions, threading, lookup |
| `SessionFeature` | each **feature** | the framework | `attach()` and `detach()`. Nothing else. |

¶20 🤖 The rule that keeps it honest: **a feature never implements a callback slot on itself.** Everything it wants to be told about is registered from inside `attach()` through the host. There is no `on_view_message` method on a feature; there is a `host.on_view_message(...)` call that registers one.

```python
class SessionFeature(ABC):
    name: ClassVar[str]
    requires: ClassVar[Tuple[Type["SessionFeature"], ...]] = ()
    exports: ClassVar[Tuple[str, ...]] = ()      # names injected onto Session
    assets: ClassVar[FeatureAssets] = FeatureAssets()

    def __init__(self, host: FeatureHost) -> None: ...
    @abstractmethod
    def attach(self) -> None: ...
    def detach(self) -> None: ...
```

```python
class FeatureHost(Protocol):
    name: str
    cwd: Optional[str]
    rows: int
    cols: int

    # --- registration (all called from attach()) ------------------------
    def on_osc(self, number: int, selector: str = "", *,
               passthrough: bool = False) -> Callable      # decorator
    def on_command_start(self, fn: Callable[[RunSession], None]) -> None
    def on_command_end(self, fn: Callable[[RunSession], None]) -> None
    def add_output_filter(self, filt: OutputFilter, *, order: int) -> None
    def add_input_filter(self, filt: InputFilter, *, order: int) -> None
    def on_view_message(self, type: str, fn) -> None
    def on_view_ready(self, fn) -> None

    # --- actions --------------------------------------------------------
    def write(self, data: bytes, *, record: bool = True, source=None) -> None
    def send_to_view(self, view, type: str, payload=None, buffers=()) -> None
    def broadcast(self, type: str, payload=None, buffers=()) -> None
    def publish_note(self, view, text: str) -> None       # new output, ONE cell
    def notes_append(self, block) -> None                 # shared second output
    def notes_status(self, key: str, text: Optional[str]) -> None

    # --- threading, owned entirely by the framework ---------------------
    def submit(self, fn, *, name: str = "") -> None       # worker thread
    def on_kernel_loop(self, fn) -> None                  # kernel io_loop
    def resolve(self, awaitable_owner, value) -> None     # thread → loop hop

    # --- cross-feature, explicit and greppable --------------------------
    def feature(self, cls: Type[F]) -> Optional[F]
```

¶30 🤖 **Threading contract** (👤 §20 ¶40): OSC handlers, filters and command-cycle subscribers run inline on the reader thread with the lock held and must not block. Blocking work goes to `submit()`; display calls to `on_kernel_loop()`. This is not advice — it is the reason the current code has three hand-rolled worker threads, and the harvest contains **two confirmed PTY deadlocks** from violating it (§95 ¶10).

¶40 🤖 `resolve()` exists because §40's `__await__` is resolved from the *reader thread* while the future belongs to the kernel's event loop. Crossing that boundary needs `loop.call_soon_threadsafe`; features must never do it by hand.

### §50.2 `core/osc.py` — the router

¶10 👤 "The signature for 2607 is always QUA. No need to have a parameter for it in the decorator." Applied — the router checks and strips `QUA` centrally and drops foreign 2607 payloads before dispatch.

```python
@host.on_osc(133, "C")        # selector = payload[:1]
def _command_started(self, ev: OscEvent) -> None: ...

@host.on_osc(2607, "O")       # QUA implied; selector = kind after the signature
def _exec_output(self, ev: OscEvent) -> None: ...

@host.on_osc(0, passthrough=True)   # title: routed AND left in the stream
def _title(self, ev: OscEvent) -> None: ...

class OscEvent(NamedTuple):
    number: int
    selector: str
    payload: str          # everything after the selector
    parts: List[str]      # payload.split(";"), pre-split
```

¶20 🤖 **Consumption rule:** a *handled* OSC is removed from the downstream byte stream by default; `passthrough=True` keeps it. An *unhandled* OSC always passes through, so terminal features quahog knows nothing about (OSC 8 hyperlinks, OSC 4 colours) still reach xterm.js.

### §50.3 `core/pipeline.py` — one filter chain, no bypass

¶10 👤 "Is that how the existing code works? That's another stupid AI design. There's no point sending OSC multiple for `exec()` to the console that's not displaying the `ExecSession` for example. Everything from the PTY should be filter-able."

¶20 🤖 Confirmed — that *is* how the current code works, and it is wrong: `_read_loop` sends the unmodified chunk to the scrollback ring, the recorder and every view, so an `exec()`'s base64 `OSC 2607;QUA;O` payloads are broadcast to every attached console. Replaced by a **single ordered chain with no verbatim tap**:

```
PTY read
   ↓
[10] OscExtractFilter (core)   → OscRouter → feature handlers
   ↓                              (consumes handled sequences)
[20] ScreenFilter              → pyte mirror; alt-screen gating
[30] RecordingFilter           → .cast tee
[40] …feature filters, by order…
   ↓
terminus sinks: scrollback ring · view broadcast · Session.streams.sink
```

```python
class OutputFilter(Protocol):
    def filter_output(self, chunk: OutputChunk) -> Optional[OutputChunk]: ...

class InputFilter(Protocol):
    def filter_input(self, chunk: InputChunk) -> Optional[InputChunk]: ...

class OutputChunk:  data: bytes
class InputChunk:   data: bytes;  record: bool;  source: Optional[ConsoleView]
```

¶30 🤖 Returning `None` swallows the chunk. Because the ring and the views now sit *behind* the chain, exec payloads never reach a console, and a re-attaching view replays clean scrollback.

¶40 🤖 Input chain, by order: dedup (10, may swallow — see §95 ¶30) → recording tee (20, may rewrite to placeholder) → interceptor observers (30) → PTY.

### §50.4 `core/commands.py` — the command cycle

¶10 🤖 The most tangled thing in the current code: `run()`, minuting and interceptors all hang off OSC 133 C/D plus the 2607 `E` text, today expressed as two rival capture slots (`active` vs `icap`) with priority rules smeared across five methods. It is core infrastructure, not a feature.

¶20 🤖 One command in flight at a time. `RunSession` **is** the per-command object (👤 §20 ¶70) — there is no second "result" type:

```python
class RunSession(AbstractConsoleOutput):
    kind = "run"
    command: str                  # from OSC 2607 E; bash corrects it in precmd
    origin: Literal["typed", "programmatic"]
    marks: Tuple[int, int]        # (combined_len at start, at end) — minute slices
    tags: Set[str]                # see ¶40
    notes: List[str]

class CommandCycleService:
    def claim_next(self, rs: RunSession) -> None   # run()/exec() pre-registration
    def on_start(self, fn) -> None
    def on_end(self, fn) -> None
```

¶30 🤖 `run()` **pre-claims** the next start rather than owning a rival slot; an unclaimed start is an interactively typed command (`origin="typed"`). The "fresh prompt while a capture is open" and "process exited mid-command" close-outs live here once, instead of at three call sites.

¶40 🤖 `tags` replaces the private `_qs_injecting` / `_qs_suppressed` attributes bolted onto results today. Any feature may stamp a tag at start; `MinutesFeature` alone decides which tags mean "do not minute" (`integration` stamps `plumbing`, `record` stamps `secret`). Core carries the set and holds no policy, so a new feature can veto minuting without `minutes/` knowing it exists.

### §50.5 Feature registration and injection

¶10 🤖 Two separate moments, and keeping them apart is the point:

- **Import time, once** — `install_feature_members(Session, FEATURES)` in `__init__.py` puts one descriptor on the `Session` class per exported name.
- **Per session** — `FeatureRegistry` topologically sorts by `requires`, constructs each feature with the host, and calls `attach()`. It stores the instances in `session._features`; it installs nothing.

¶20 🤖 A single descriptor covers methods and properties alike, because `getattr(feature, name)` yields a bound method for one and the computed value for the other:

```python
class FeatureMember:
    """Class-level trampoline resolving to the per-session feature instance."""

    def __init__(self, feature_cls, name, doc=None, writable=False): ...

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self                       # class access: the descriptor, doc intact
        return getattr(self._owner(obj), self._name)

    def __set__(self, obj, value):            # data descriptor: precedence is unambiguous
        if not self._writable:
            raise AttributeError(f"{self._name!r} is read-only")
        setattr(self._owner(obj), self._name, value)

    def _owner(self, obj):
        try:
            return obj._features[self._feature_cls]
        except KeyError:
            raise AttributeError(
                f"{self._name!r} needs the {self._feature_cls.__name__} feature, "
                f"which is not enabled for this session") from None


def install_feature_members(session_cls, feature_classes):   # called ONCE
    for fcls in feature_classes:
        for name in fcls.exports:
            member = getattr(fcls, name)
            is_prop = isinstance(member, property)
            doc = (member.fget.__doc__ if is_prop else member.__doc__) or ""
            writable = is_prop and member.fset is not None
            setattr(session_cls, name, FeatureMember(fcls, name, doc, writable))
```

¶30 🤖 `writable` is derived from whether the feature declares a property setter, so `h.minuting = False` works while `h.recording = True` raises `'recording' is read-only` rather than silently shadowing. Defining `__set__` unconditionally makes it a **data** descriptor, so an accidental instance attribute can never shadow a feature member — the failure mode a non-data descriptor would have.

¶40 🤖 `Session` therefore mentions no feature and declares no feature member — `core/session.py` is construction, the Popen face, and `_ipython_display_`. Its static surface lives in the generated `core/session.pyi` (§30 ¶45).

¶50 🤖 One caveat, measured: because members are installed on the class, TAB offers names belonging to features **not enabled for this particular session**; accessing one raises the informative `AttributeError` above. Moot while the feature list is global (§30 ¶30) — it only bites if per-session feature subsets are ever introduced, and the error message is already written for that day.

## §60 The front-end API

¶10 👤 "They will separately contribute JS and CSS as well, instead of having one big file"

¶20 🤖 `core/console.js` owns the `Terminal`, the bar, fit/resize, scrollback replay, the exited/input badges and a message router. Features register through a small `api`:

```js
// record/record.js
export default {
  name: "record",
  init(api) {
    const rec = api.addButton({ id: "rec", label: "Record", icon: SVG.record,
                                onClick: () => api.send("toggle") });
    api.onMessage("state", (msg) => { /* … */ });
    api.onMessage("echo",  ()    => api.flash(rec));
  },
  dispose() {},
};
```

¶30 🤖 `api`: `addButton`, `addBadge`, `send(type, payload)`, `onMessage(type, fn)`, `flash(el)`, `term`.

¶40 🤖 Envelope is `{feature, type, …}`, stamped automatically in both directions, so routing is mechanical. Today's flat `{"type": "rec-state"}` becomes `{feature: "record", type: "state"}`.

¶50 🤖 The input badge and the OSC 0/2 title stay in **core** — neither is a toolbar button, both are session-lifecycle facts. The harvest is explicit that OSC 1 (icon name) must *not* be revived: it was built, browser-verified, then deleted because an embedded console cannot be iconified.

## §95 Harvested findings that constrain this design

¶10 🤖 **Two confirmed PTY deadlocks** in the injection path: the reader thread re-entered a non-reentrant lock via `sendline`→`_input`; and typing a ~4.3 KB payload inline stopped the reader draining, the shell's echo filled the output buffer, the shell stopped reading, and both ends wedged forever. Root-caused with a real thread dump, not guessed. → §50.1 ¶30 is load-bearing.

¶20 🤖 **Injection transmission is empirical, not theoretical.** Type-ahead into a fresh PTY is lost (0/5 in zsh at every delay tested) — must wait for quiescence (6/6 both shells). Large payloads need chunked, flow-controlled writes (4/4); naive line-by-line fails on macOS bash 3.2 (0/4) and raw fast writes corrupt the script in transit. Bracketed paste is unsupported there. A literal `!` anywhere in the line triggers bash history expansion *before parsing*, so quoting cannot save it. → port `integration/` verbatim.

¶30 🤖 **Terminal-reply duplication** was misdiagnosed twice: blamed on multiple views, then disproven when one view reproduced it. Real cause was vim retrying its capability probe after a client-side timeout, all replies landing in one burst. Fix: recognise reply *shapes* by regex and dedup within ~150 ms regardless of source. → input filter at order 10.

¶40 🤖 **Foreground exec cannot key completion off the `X` (rc) marker** — `X` arrives before the shell's `D`, so a back-to-back `exec()` sees the session still busy. Background exec needs a `( … & )` subshell to suppress bash's `[1] <pid>` notice *and* an internal wait for the launch prompt.

¶50 🤖 **`os.write()` to a PTY master does partial writes** on large buffers — uploads hung until a write-all loop was added. **bash's DEBUG trap never fires for a bare function definition**, so `run("foo() { …; }")` blocks forever. **`_echo_on()` must require ECHO off *and* ICANON on** — readline runs with both off, so the naive rule would suppress recording of every command.

¶60 🤖 **Do not resurrect the ssh `ControlMaster` design.** A control socket is local to the host running the ssh client, so one created several manual hops deep is physically unreachable from the kernel. That fact invalidated an entire built-and-tested milestone.
